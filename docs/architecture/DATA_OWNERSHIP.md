# Data Ownership Map

**Status:** CURRENT  
**Rule:** One authoritative owner per concept. Projections must be recoverable from SoT.  
**Related:** ADR-003/004/005/006/011, [`ORA_CURRENT_STATE.md`](../ORA_CURRENT_STATE.md)

### Legend

| **Ephemeral Projection** | Cache/index; may be rebuilt or expire |

## Hard rules (prevent Cursor mistakes)

1. Do **not** put assignment or ride state winners in Redis.
2. Do **not** treat Redis GEO as proof a driver is “available” without Firestore `availabilityState` + approval.
3. Do **not** write GPS history into Firestore unless a new phase freeze says so (N2A cursors only today).
4. Do **not** assume RTDB paths exist because ADRs mention them.
5. Outbox `PENDING` is not “delivered.”
6. Do **not** add a Firestore geo fallback for N3 Redis outages (fail closed with `DEPENDENCY_ERROR`).
7. Do **not** expose exact driver coordinates on passenger JWT routes (N3 MVP is internal-only).
8. Do **not** invent a `homeCity` writer as part of N3 — seeding remains an ops/onboarding dependency (D7).
9. Do **not** treat N3 candidates as assignment authority — assignment remains Firestore offer/select.
10. Do **not** implement N4 wave code until an explicit implementation prompt follows the freeze in `n-series/N4-dispatch-planning.md` (coordinate-primary candidates; delivery wake-up is out of N4 MVP).
11. Do **not** let N4 write `assignedDriverId` or auto-create `rideOffers`.
12. Do **not** treat Redis as the invite SoT — use `rideDispatchWaves` (conceptual) once implemented.
